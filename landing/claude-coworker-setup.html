1. Account and workspace check

Before we build anything, we need a clean container. You are on a work laptop, so we are going to treat privacy and file location as part of the setup — not an afterthought.

A. Confirm the account is the right one

  • Confirm he is logged into the Claude account he will actually use for work.
  • If the company provides a Claude Team/Enterprise workspace, use that instead of a personal account.
  • If he only has a personal/pro account, keep this setup limited to non-sensitive online/public/business-reference material until company policy is clear.
  • Confirm plan supports the needed features: Projects, file upload, connectors/tools, artifacts, and/or Claude Desktop if needed.

B. Decide where work lives

  • Primary home: create one Claude Project for the client/business workflow. This is where reusable instructions, uploaded reference files, and recurring prompts live.
  • Source of truth: keep original files in the company-approved cloud system — Google Drive, OneDrive, SharePoint, Notion, or the company knowledge base. Claude gets copies or connector access; it should not become the only place a file exists.
  • Local laptop rule: do not store client docs, exports, transcripts, or downloaded AI outputs in random local folders like Downloads/Desktop. If something must be saved locally, put it in a clearly named work-approved folder and delete temporary copies after the session.
  • Online-data rule: since he is only using online data, prefer links, cloud docs, and connector access over downloading/uploading files manually.
  • Project naming: use a boring obvious name like “Work AI Coworker — [Business/Team]” so he can find it later.

C. Set privacy boundaries before connecting tools

  • Open Claude settings and review privacy/data controls, retention settings, and any admin/workspace policies available on his plan.
  • Do not connect every app. Connect only what supports the first workflow.
  • Start with low-risk reference material: public website pages, approved docs, templates, process notes, and examples he is comfortable using.
  • Avoid uploading passwords, private customer data, HR data, medical/financial records, legal documents, unreleased strategy, or anything his company would not want pasted into a web app.
  • If a file contains sensitive details but the workflow is useful, make a sanitized copy first: remove names, account numbers, private customer details, and internal financials.
  • When in doubt, ask: “Would I be comfortable emailing this document to an outside consultant?” If no, do not put it into Claude yet.

D. Run a safe access test

  1. Open the Claude Project.
  2. Add one harmless online reference: company website page, public FAQ, or approved process doc.
  3. Ask Claude to summarize what it can see and list what it cannot see.
  4. Confirm he understands the boundary: Claude can only use what is in the chat/project or connected through approved tools.
Recommended rule
Files live in the company-approved cloud workspace. Claude Projects hold working context, copies, instructions, and prompts. The laptop is temporary. Downloads/Desktop are not storage.
Success looks like
He can open the right Claude account, find the right Project, understand where files live, upload or connect one safe reference, and explain what should not go into Claude.

2. Create the main Claude Project

Project name: Business Coworker Purpose: Help with recurring business work, writing, planning, summaries, follow-up, research synthesis, and decision support.

Project instructions

You are my business coworker. Help me think clearly, move faster, and keep my voice. Ask clarifying questions when the task is vague. Prefer practical drafts, checklists, summaries, and next actions. Do not over-polish my writing unless I ask. When editing, preserve my meaning and voice. When facts matter, separate sourced facts from assumptions. If a task should become a reusable prompt or workflow, suggest that.

3. Add foundation files

  • About the business: services, customers, offers, pricing, common objections.
  • Voice samples: 3-5 emails/posts/docs that sound like him.
  • Current goals: this quarter’s priorities and what success means.
  • Recurring workflows: reports, follow-ups, proposals, meeting notes, content, admin.
  • Rules: things Claude should avoid, compliance/privacy boundaries, approval steps.
Create a short “How to work with me” document from these notes. Organize it into: voice, goals, recurring tasks, preferences, do-not-do rules, and examples.

4. Locate connectors and tools

  1. Open Claude settings.
  2. Look for Connectors, Integrations, Tools, or Connected apps.
  3. Connect only what supports the first workflow. Do not connect everything just because it exists.
  4. Likely candidates: Google Drive, Gmail, Calendar, Slack, Notion, GitHub, Canva, Zapier, or MCP tools depending on his setup.
  5. After connecting, test with a harmless lookup: “Can you see [known non-sensitive file/event]?”
Rule
Access follows workflow. First decide what job Claude should do, then connect the minimum tools needed for that job.

5. Find and set up skills / reusable prompts

  • Look for Claude Skills if available on his plan/account.
  • If Skills are unavailable, use Project instructions + saved prompt blocks as the fallback.
  • Create 3 starter reusable prompts: meeting summary, email cleanup, decision brief.
  • Name prompts plainly so he can find them later.
Starter saved prompts: 1. Clean this up but keep my voice 2. Turn this meeting into follow-up tasks 3. Help me build a better prompt before answering

6. Build the first workflow

  1. Pick one recurring task from the assessment.
  2. Gather one real example.
  3. Run the meta prompt.
  4. Save the final prompt in the Project.
  5. Run it once with real material.
  6. Ask: What would make this better next time?

7. Success checklist

  • Claude Project created.
  • Project instructions pasted.
  • At least 3 useful files uploaded.
  • Relevant connector checked or intentionally skipped.
  • One reusable prompt saved.
  • One real workflow completed during the call.
  • Next follow-up task assigned.
If we leave with one reliable workflow, the setup worked. We can add more later.
